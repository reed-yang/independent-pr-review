# Project review policy

Report introduced, actionable correctness, security or data-loss bugs with a
concrete trigger and consequence. Check supplied callers, tests and existing
guards. Do not report formatting preferences, speculative refactors or pre-existing
bugs. Missing context limits confidence. Keep all review prose in English.

Replace this file with your project's invariants. Scope specialist policies by
path in review.json; do not copy another project's product assumptions.
